# Petstore TestRail Test Execution Project

## Project Overview

This repository represents a complete manual QA testing project executed using TestRail for the Petstore demo web application.  
The project demonstrates a full end-to-end Software Testing Life Cycle (STLC) including test planning, test case design, test execution, metrics analysis, dashboard visualization, and final test closure.

The primary objective of this project is to showcase practical TestRail usage, structured QA documentation, execution tracking, and professional reporting following industry-standard QA practices.

---

## Application Under Test (AUT)

**Application Name:** Petstore Demo Web Application  
**URL:** https://petstore.octoperf.com  
**Application Type:** Web-based demo e-commerce system  

### Key Functional Areas
- Browse pet categories (Bird, Reptile, Cat, Dog, Fish)
- View product listings and product details
- Add products to cart
- Update cart (quantity, remove items)
- Checkout process and order flow

---

## Tools & Technologies Used

- Test Management Tool: TestRail  
- Testing Type: Manual Functional Testing  
- Browser: Google Chrome  
- Operating System: Windows  
- Documentation: PDF, Excel  
- Visualization: TestRail built-in charts, Excel dashboard  

---



## Test Planning

A detailed Test Plan was created before starting execution.  
The test plan defines:
- Test objectives
- In-scope and out-of-scope areas
- Test strategy
- Test environment
- Entry and exit criteria
- Risks and assumptions  

This ensured a structured and controlled testing process.

---

## Test Case Design

- Test cases were designed and managed directly in TestRail  
- Each test case includes:
  - Preconditions
  - Detailed test steps
  - Expected results
  - Priority and labels  

### Test Case Modules
- Browse Categories
- View Product Details
- Add to Cart
- Update Cart
- Checkout Process

---

## Test Execution

All test cases were executed manually using TestRail.  
Each test case was marked with one of the following statuses:
- Passed
- Failed
- Blocked
- Skipped  

Execution comments were added wherever applicable to capture observations and limitations.

## QA Metrics Summary

- Requirement Coverage: 100%

## Test Closure & Reporting

After completion of execution:
- A final Test Summary and Closure Report was prepared
- Overall application quality was assessed
- Risks and limitations were documented
- A Conditional Go recommendation was provided  

This formally marked the closure of testing activities.
